# HeisenWorks Design Report

Date: 2026-11-22. Scope: `heisenworks_frontend` (homepage plus 8 subpages, 404, redirects).
Nothing here is committed; all changes are in the working tree.

## 1. What the site is

HeisenWorks (heisenworks.in) is an independent web and digital studio. It is a static multi-page site: plain HTML, CSS and vanilla JS, Lenis smooth scroll, a hero video loop, Vercel serverless functions for the contact form and Google reviews. Identity: near-black `#090a0c` and white surfaces, amber `#cf8047` accent, Instrument Serif / Onest / JetBrains Mono.

## 4. Changes by skill

**design-taste-frontend (used as a review lens).** The skill is a from-scratch build pipeline; running its full gate would have rebuilt the site, which you did not ask for. I applied its principles to the real code: no invented content, brand and structure kept, nothing generic added, the nested-pill defect fixed.

**ui-ux-pro-max (tokens and contrast), applied by measurement.** Contrast was measured per element in a real browser (not estimated).
- New tokens in `css/shared.css`: `--amber-ink #9c4f1b` (amber text on light, 5.9:1 on white), `--text-muted-dark #8b95a5` (muted text on dark, 6.5:1), `--ease-out`.
- Amber text on white was 3.07:1 (team eyebrow, `01` indices, services numbers, experience pills) → `--amber-ink`.
- White on amber buttons was 3.07:1 (team WhatsApp, 404 CTA, `.pill-btn-amber`) → dark ink `#1a0f07` (about 6.4:1), with a lighter hover so the contrast holds.
- `#64748b` on dark (footer, nav menu) was 3.9–4.2:1 → `--text-muted-dark`.
- Translucent home labels raised: clock, hero card caption, socials, hero status bar, services description and number, modal note, form label, review date, nav menu index.
- 10px functional text raised to the 11px floor (project tag chips, pricing badges, hero card caption).

**emil-design-eng (motion polish).**
- Buttons now press: `.pill-btn:active` scales to 0.97 on a 160ms strong ease-out; also on the team WhatsApp CTA and the 404 buttons.
- Removed all three `transition: all` (hero dashes, portfolio meta, 404 buttons); each lists its properties.
- Reduced motion: the old rules killed every transition and animation globally in two places. Now one rule in `shared.css` stops movement but keeps short opacity, colour and shadow feedback.

**animate.** I reviewed motion with its "should this animate at all" test and added no new animation. The site already has a loader, hero entrance, cursor glow, scroll reveals and card loops. More motion would cost performance and hurt the one-moment-per-page restraint. The motion work was subtraction and correction.

**web-design-guidelines (final gate).**
- Added `name` and `autocomplete` (and `spellcheck=false` on email) to every form field on all pages.
- One global `:focus-visible` amber ring, because several controls set `outline: none`.
- Skip link plus `id="main"` on every page; skip-link CSS moved into `shared.css`.
- Added `aria-label` to the star-rating select.
- Heading levels fixed: `/work` project titles and the `/team` experience card were `h3` straight after `h1`.
- Footer and legal links have a 24px hit area; the nav-menu "Start a project" button is 44px tall.

## 5. Left standing, with reasons

| Item | Why it stays |
|---|---|
| Hero and footer watermarks, `Build` / `Better` tiles, separator dot, the `✆` glyph | Decorative or mid-reveal text; the scan flags them but they carry no information. |
| Review stars (about 2.1:1) | Graphics next to a numeric rating. Darkening them changes the Google-rating look; your call. |
| Kicker-above-heading in 6 places | A consistent brand pattern, not a defect. Consider varying it in a redesign. |
| Icon tiles above headings on `/team` | Generic pattern; replacing it is a redesign decision. |
| `.tp-hero-glow` "overflow" | False positive: its parent has `overflow: hidden`. |
| Pricing "flat type hierarchy" | False positive: the page `h2` is already `clamp(2rem, 4vw, 2.75rem)`. |
| Honeypot inputs "unlabeled" | Intentionally hidden (`display:none`, `tabindex=-1`). |
| `team.html` is 70 KB, 9 MB `zod-living-walkthrough.mp4`, 2.3 MB hero loop | Performance work: needs a decision on video re-encoding and lazy loading. Not changed. |

## 7. How to work on the site now

- Edit only `heisenworks_frontend/pages/*.html` (and `index.html`, css, js).
- After editing a page, run `node heisenworks_frontend/scripts/restore-routes.mjs`, then commit `pages/` and the regenerated copies together; `--check` fails if any copy is stale.
- `node heisenworks_frontend/scripts/server.mjs` serves the site the way production does.
